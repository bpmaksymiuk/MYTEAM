### Stage 9 deviations from upstream design
- **AR-006 / DI-018 (Chart.js vendor)**: No Chart.js distribution was available locally in the build environment. Rather than introduce a network fetch at runtime, `dashboard.js` was implemented with raw `Canvas 2D` line-chart and stacked-bar drawing. This satisfies BR-020 through BR-026 (multi-series live populations, biomass-by-trophic, alert panel) without an external library. The `./build/vendor/` directory is reserved for a future Chart.js drop-in if richer interactivity (e.g. legend isolation toggle) becomes required.
- **DI-005 plant model**: Plants are modelled as patch records with a density field rather than as full agents (consistent with DI-005 step 3 and species `isPlant: true`). Algae bloom is implemented by accelerating patch density growth when nutrient > 1.8.

### Known limitations
- Pop charts smooth at one sample per simulated day; rapid sub-day swings are not visualised.
- Food-web initial layout uses a simple x-relaxation pass; complex graphs may show overlap.
- The on-canvas food-web overlay (per-frame predator-prey arrows) is decoupled from the food-web screen graph; both share predation-log data only.

## v0.2.0 — Vibrant cartoon graphics (UC-015, UC-016, UC-017)

### Implemented (PT-019..PT-029)
- `./build/assets.js` (PT-019) — async preloader for sprite-sheets, portraits, UI icons. Boot gate.
- `./build/animator.js` (PT-020) — per-agent animation FSM (idle/walk/swim/flight + facing flip + frame advance scaled by simulated dt).
- `./build/sprites/*.png` + `./build/sprites/manifest.js` (PT-021, PT-029) — 28 cartoon sprite-sheets generated by `scripts/gen-sprites.py`.
- `./build/images/ui/*.svg` (PT-022) — 16 cartoon UI icons (nav 6, time 6, overlay 4) + 6 event icons + 5 scenario header illustrations.
- `./build/images/portraits/*.svg` (PT-023) — 28 species portraits (idle frame embedded as base64 inside SVG wrapper).
- `./build/renderer.js` (PT-024) — replaced `ctx.arc` agent draw with `drawImage` against the per-species sprite-sheet using current animator frame; viewport culling; horizontal flip for facing.
- `./build/style.css` (PT-025) — cartoon palette tokens, chunky rounded buttons (≥36 px), squash on press, focus ring, polaroid save slots, scenario card layout, lily-pad loading spinner, `prefers-reduced-motion` honoured.
- `./build/index.html` (PT-026) — added loading overlay, swapped text-only buttons to icon+label, added portrait/event-icon `<img>` slots.
- `./build/main.js` (PT-027) — `await loadAssets(...)` boot gate before sim starts; loading progress percentage.
- `./build/inspector.js`, `./build/intervention.js`, `./build/foodweb.js`, `./build/scenarios.js` (PT-028) — portraits in inspector header (96×96), intervention rows (32×32), food-web nodes (~28 px), scenario cards get illustrated headers.
- `./build/sim.js` — calls `initAnim` on `spawnAgent` and `updateAnimator` per agent per tick.
- `./build/storage.js` — re-runs `initAnim` on every restored agent after `loadSlot` (animator state is intentionally not serialised — AR-014).
- `./scripts/gen-sprites.py` (DI-024) — deterministic Python+Pillow generator for all sprites and portraits.

### Stage 9 deviations
- **Sprite art quality**: programmatic cartoon renderings (geometric primitives) rather than hand-painted illustration. Distinct silhouette + palette per species satisfies BR-093 distinguishability; hand-painted replacements may drop in later without code change.
- **Plant locomotion**: plant species have empty `loco: []` — they still get a sprite-sheet (idle row only) but the animator skips them because their agent records are not in `state.agents` (plants are tracked in `state.plantPatches`). Plant idle motion is delivered via the renderer's `patch.phase` wobble (AR-017) rather than a sprite-sheet animation per BR-096.
- **Locomotion table**: rather than editing 28 records in `species.js`, the per-species `loco` array is read from `./build/sprites/manifest.js`. This keeps `species.js` untouched and makes the locomotion declaration co-located with the sprite-sheet rows it depends on.

## v0.3.0 — Living dams, procedural terrain, plant sprites, vibrant atmosphere (UC-018..UC-021)

### Implemented (PT-030..PT-039)
- `./build/terrain.js` (PT-030) — seeded Perlin-noise biome generator, 6 zone types, seasonal offset, `zoneAt`, `buildTerrainImageData`.
- `./build/particles.js` (PT-031) — particle pool (max 1200); emitRipple, emitSplash, emitBlink, emitRain, emitConfetti; `PM_REDUCED` guard.
- `./build/sprites/plant-*.png` + manifest entries (PT-032, PT-039) — 10 plant sprite-sheets with idle/seasonal-winter/harvest rows; generated via extended `gen-sprites.py`.
- `./build/renderer.js` (PT-033) — 8-layer render pass: sky-bg, terrain ImageData, dams, plant sprites, animals, particles, overlays, time-of-day tint.
- `./build/sim.js` (PT-034) — zone-affinity spawn, `tickAllDams`, `demolishDam`, particle emit on predation/ripple/blink/rain.
- `./build/state.js` (PT-035) — `state.terrain`, `state.dams`, `state.milestones` fields.
- `./build/main.js` (PT-036) — seed read from `#seed=N` URL hash (or generate), terrain init after loadAssets, canvas click → dam tooltip, tickParticles in game loop.
- `./build/index.html` (PT-037) — `#seed-chip`, `#dam-tooltip`, `#ambient-eq` (5 bar spans).
- `./build/style.css` (PT-038) — `.seed-chip`, `.dam-tooltip`, `.ambient-eq` + `@keyframes eq-pulse`, reduced-motion guard.
- `./build/environment.js` — calls `applyTerrainSeason` on season change.

### Stage 9 deviations
- **Dam auto-initiation**: rather than requiring the scenario panel, beavers auto-create dams stochastically (p=0.0001/tick when no dam within 200px, max 3). Scenario-panel initiation remains in `beaverdam.js` for the "Beaver Dam" guided scenario.
- **Terrain resolution**: biome map is full canvas resolution (Uint8Array of W×H). Recomputed only when `state.terrain.dirty` is set (season change or new game). Offscreen canvas cached.
- **Plant `phase` initialisation**: `patch.phase` is now driven by the renderer (incremented by 0.016 each frame). Existing patches that lack a `phase` property default to 0 and start animating immediately.
